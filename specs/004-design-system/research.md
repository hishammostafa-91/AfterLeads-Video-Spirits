# WP-04 Research — D1..D14

All decisions cite canonical sections; versions verified against the 00 §0.8 baseline rows and the existing `app/package.json`/toolchain (G-10). Registry-resolved exact pins land at implementation and lock into `app/pnpm-lock.yaml`.

- **D1 — Dependency set and activation of the UI gates.** **Decision**: add exactly the baseline rows — `react-aria-components` 1.22.x, `react-intl` 12.x, `zustand` 5.x; dev: `vitest` 5.x, `@testing-library/react` 16.x, `jsdom` 30.x, `@playwright/test` 1.64.x, `@axe-core/playwright` 4.x, `eslint` 9.39.x, `typescript-eslint` 8.x, `eslint-plugin-jsx-a11y` 6.x, `eslint-plugin-react-hooks` 7.x, `eslint-plugin-i18next` 6.x, `eslint-plugin-formatjs` 8.x, `stylelint` 17.x, `stylelint-config-standard` 40.x, `stylelint-use-logical` 2.x, `prettier` 3.x, `@formatjs/cli` 6.x. **Rationale**: 00 §0.8 pins these rows with their reasons; `tools/verify.ps1` activates `ui-typecheck`/`ui-lint`/`ui-test`/`i18n` purely by the presence of `typecheck`/`lint`/`test`/`i18n:check` scripts in `app/package.json` (verified by reading the gate block) — defining them is the switch. **Alternatives**: adding `dockview` now (rejected — WP-05's composition concern, G-02); any virtualization library (rejected — not a baseline row, see D10).
- **D2 — Theme/accent mechanism.** **Decision**: `tokens.css` defines the token custom properties twice — `[data-theme="dark"]` (07 §7.4.1 values) and `[data-theme="light"]` (§7.4.2) — plus the timeline/media tokens per theme (§7.4.4) and the shared type/space/motion tokens (§7.4.5–7.4.6); accents swap `--accent-solid/text/subtle` via `[data-accent="clr-06|07|04|02|08"]` blocks using the §7.4.1/§12.17 values. High Contrast is not a data-theme: a `@media (forced-colors: active)` block maps the tokens to system colors (§7.4.3) and activates with Windows contrast themes without any attribute. A Zustand `themeStore` sets `data-theme`/`data-accent` on `<html>`; switching is an attribute swap — no reload, satisfying REQ-APP-009's no-restart rule. **Rationale**: custom properties cascade and re-resolve on attribute change; the forced-colors media query is the platform's own signal (§7.4.3 "When `forced-colors: active` … tokens map to system colors"). **Alternatives**: CSS `color-scheme`-only theming (insufficient — the token set is much larger), a third `data-theme="high-contrast"` value (rejected — §7.4.3 keys High Contrast to forced colors, and duplicating system colors by hand drifts).
- **D3 — Application zoom 80–200%.** **Decision**: apply the standardized CSS `zoom` property on the app root element (`zoom: calc(var(--app-zoom) / 100%)` with `--app-zoom` clamped 80–200), driven by the same theme store; per-monitor DPI is left to WebView2's native device-pixel handling — all icons are SVG and all fonts variable, so scaling stays crisp (REQ-APP-010). **Rationale**: `zoom` re-runs layout and scales px tokens, `rem`, and borders together (a `transform: scale` alternative clips and does not affect layout); it is standardized (CSS Viewport spec) and supported in WebView2/Chromium; the harness snapshots pin zoom at 100 for determinism. **Alternatives**: root `font-size` scaling (rejected — 07 §7.4.5 sizes are px tokens and would not scale), `transform: scale` (rejected — breaks hit-testing and scrolling).
- **D4 — i18n runtime and runtime language switch.** **Decision**: all six locale JSONs are statically imported into a typed registry (`{ en, ar, fr, es, de, "pt-BR" }`); an `IntlProvider` wrapper (react-intl 12) takes locale + messages from a `localeStore`; switching updates the store, which re-renders and sets `lang`/`dir` via `direction.ts` (07 §7.11) — no reload (REQ-I18N-001). The default resolves the Windows display language (`navigator.language`/`navigator.languages`) to a LOC-01..06 match, else `en`. **Rationale**: six small catalogs make static imports simpler and offline-safe (constitution VII); runtime switch is a provider prop change. **Alternatives**: dynamic `import()` per locale (unnecessary complexity at this size; revisit at WP-25 if catalogs grow).
- **D5 — Locale key discipline and CI check.** **Decision**: `app/src/locales/en.json` is the source; each other file must carry the exact same key set; `en.meta.json` carries one translator description per key (07 §7.12 rules 2/4). `pnpm -C app i18n:check` runs a small node script: deep key-set equality across all six + (every `en` key has meta) + (no raw literals drift) — nonzero exit on any mismatch (REQ-I18N-004). `@formatjs/cli extract` is available for authoring but is not a gate. **Rationale**: the requirement is set equality, which is exactly checkable; the script backs the existing `i18n` verify gate. **Alternatives**: per-key fallback tolerance (rejected — REQ-I18N-004 says CI fails on missing or extra).
- **D6 — Component inventory mapping to React Aria Components.** **Decision**: RAC 1.22 supplies the interactive core: Button, ToggleButton, Menu/MenuTrigger/Popover, Tabs, Dialog/AlertDialog, Tooltip, NumberField, Slider, Checkbox, Switch, RadioGroup, Select, ComboBox, SearchField, TextField, TextArea, GridList, Table, ListBox, ProgressBar, Meter, Spinner, Tree. Composed on top (RAC primitives + custom DOM): SegmentedControl (RadioGroup-styled), IconButton (Button + icon + Tooltip + accessible name), Toast (region + announcer), TimecodeField (four segmented fields, always `dir="ltr"`, scrub + typed/relative entry), KeyframeToggle/Navigator, ColorPicker (HSV square + hue + hex/RGB + recent colors), ColorWheel, CurveEditor (SVG), PointControl, Skeleton, Badge (text+icon), EmptyState, and the windowing collections wrapper (D10). **Rationale**: 07 §7.6 mandates RAC for interactive primitives; the specialist controls are domain widgets the doc itself describes functionally. **Alternatives**: headless reimplementation of menu/dialog semantics (rejected — loses the ARIA/RTL guarantees REQ-A11Y-002 relies on).
- **D7 — Harness and deterministic snapshots.** **Decision**: a `/harness` route (`HarnessApp`) renders a story grid from `src/harness/stories/` (one file per component, nine states each: default, hover, focus-visible, pressed, disabled, error, RTL, compact, high-contrast); query params `?theme=dark|light&locale=<tag>&density=` select the rendering mode, so Playwright projects enumerate the dark/light × en/ar matrix by URL. Playwright config: fixed viewport 1280×720, `reducedMotion: 'reduce'`, `colorScheme` per project, `await document.fonts.ready` before capture, `expect.toHaveScreenshot()` per story. `@axe-core/playwright` runs `axe()` per story in the same pass; any violation fails (T-A11Y-004, SC-006). **Rationale**: URL-driven modes reuse one build; reduced motion + awaited fonts + fixed viewport remove the classic flake sources (constitution III). **Alternatives**: per-mode builds (slow, drift-prone), component-test runners (no real CSS cascade).
- **D8 — Lint/build enforcement stack.** **Decision**: flat `eslint.config.js` (ESLint 9.39) with `typescript-eslint` strict-type-checked, `react-hooks`, `jsx-a11y` (errors), `eslint-plugin-i18next/no-literal-string` (JSX text literals error), `eslint-plugin-formatjs` (message-id hygiene); `.stylelintrc.json` (Stylelint 17 + `stylelint-config-standard` 40 + `stylelint-use-logical` 2 — physical margin/padding/etc. autofixed-flagged as errors); `.prettierrc.json` (Prettier 3) with `prettier --check` folded into the `lint` script so the single `ui-lint` gate covers formatting. `typecheck` = `tsc --noEmit` (strict, no `any`). **Rationale**: 02 §2.14 names each rule; the verify gates call exactly these scripts. **Alternatives**: separate format gate (none exists in verify.ps1 — folding keeps one command green).
- **D9 — Fonts FNT-01..03 bundling.** **Decision**: bundle variable woff2 files from the official upstream repositories (Inter: rsms/inter releases; Noto Sans Arabic: google/fonts repo; JetBrains Mono: JetBrains/JetBrainsMono releases) as separate files with each family's `OFL.txt` into `assets/fonts/`; a committed `fonts.json` records `{ id, family, file, sourceUrl, sha256, licenseFile }` per 12 §12.16; `fonts.css` declares `@font-face` with the §7.4.5 stacks and `font-display: swap`; the Arabic `:lang(ar)` line-height/size adjustment lives in tokens.css (§7.4.5). A small check (folded into `i18n:check`? no — into `test`) re-hashes the files and fails on mismatch (spec edge case). **Rationale**: 12 §12.16 pins OFL, separate files, license files, and the manifest "at WP-04"; bundled = no runtime download (constitution VII). **Alternatives**: npm font packages (indirect provenance — the doc names upstream repositories + recorded hashes).
- **D10 — List virtualization beyond 200 rows.** **Decision**: implement a small `useWindowing` hook (container measurement + row height + overscan window; render window only) used by Tree/GridList/Table/ListBox above 200 rows (07 §7.6). **Rationale**: no virtualization library exists in the 00 §0.8 baseline; adding one needs an owner ADR (G-11/G-17); the doc's requirement is a threshold behavior, not a library. **Alternatives**: `react-virtuoso`/`@tanstack/virtual` (both rejected — not baseline rows; revisit via ADR only if the custom hook proves insufficient in WP-08's real timelines).
- **D11 — Mock backend skeleton.** **Decision**: `src/harness/mock/` exports typed fixture factories (media items, jobs, markers) shaped by the existing `src/ipc/bindings` types where they exist, plus a stub event bus — just enough for stories (badges, progress, lists, empty states); no IPC calls. **Rationale**: the card's "mock backend skeleton" is story data, not a fake server; the bindings keep fixtures honest to the model. **Alternatives**: a full command-mock layer (WP-05's need, not ours).
- **D12 — Theme/locale persistence seam.** **Decision**: `themeStore`/`localeStore` (Zustand 5) expose `set()` plus a storage seam interface (`read()/write()`); the harness binds the seam to URL query params; the app later binds it to `alvs.appearance.*` settings keys (WP-05/WP-24). **Rationale**: REQ-APP-009/REQ-I18N-001 need persistence to exist without inventing the settings wiring that belongs to later packages (FR-018 fence). **Alternatives**: reading `settings.json` now (rejected — storage ownership is WP-05's startup, CMP-12).
- **D13 — Accessibility infrastructure.** **Decision**: `components/a11y.ts` mounts the two live regions (polite for edits/jobs, assertive for errors — §7.13 rule 3) at the harness root and exports announcement helpers; focus ring comes from `--focus-ring` on `:focus-visible` (§7.13 rule 1); landmarks (banner/toolbar/region/status) are laid out by `HarnessApp` (§7.13 rule 2). Canvas `role="application"`/`aria-roledescription` patterns are documented in the contracts for WP-08+ consumers (§7.13 rule 4). **Rationale**: REQ-A11Y-002's "(components)" share is exactly the primitives + live-region infrastructure later screens reuse.
- **D14 — Pseudo-locales LOC-90/91.** **Decision**: `i18n/pseudo.ts` generates `en-XA` (accented Latin, +40% length, wrapping brackets) and `ar-XB` (RTL with bidi marks) from `en`/`ar` at test time (pure string transforms per 12 §12.14's descriptions); loaded only in test/harness builds via the registry; the expansion test renders toolbar/button labels under LOC-90 (07 §7.12 rule 5). **Rationale**: generated = cannot drift from the source catalog; test-only per the LOC table's Status column. **Alternatives**: checked-in pseudo files (drift; rejected).

**Zero unresolved clarifications** — the spec's assumptions cover the remainder.
