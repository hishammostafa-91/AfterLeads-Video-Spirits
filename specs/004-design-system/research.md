# WP-04 Research — D1..D16

All decisions cite canonical sections; versions verified against the 00 §0.8 baseline rows and the existing `app/package.json`/toolchain (G-10). Registry-resolved exact pins land at implementation and lock into `app/pnpm-lock.yaml`.

- **D1 — Dependency set and activation of the UI gates.** **Decision**: add exactly the baseline rows — runtime: `react-aria-components` 1.22.x, `react-intl` 12.x, `zustand` 5.x, `lucide-react` 1.x (ISC; the 07 §7.5 base icon set — review F01); dev: `vitest` 5.x, `@testing-library/react` 16.x, `jsdom` 30.x, `@playwright/test` 1.64.x, `@axe-core/playwright` 4.x, `eslint` 9.39.x, `typescript-eslint` 8.x, `eslint-plugin-jsx-a11y` 6.x, `eslint-plugin-react-hooks` 7.x, `eslint-plugin-i18next` 6.x, `eslint-plugin-formatjs` 8.x, `stylelint` 17.x, `stylelint-config-standard` 40.x, `stylelint-use-logical` 2.x, `prettier` 3.x, `@formatjs/cli` 6.x. Installation goes through the **root pnpm workspace** (`pnpm-workspace.yaml` already lists `app`): the **root `pnpm-lock.yaml`** is updated and committed — there is no per-package lockfile (review F04). **Rationale**: 00 §0.8 pins these rows with their reasons; `tools/verify.ps1` activates `ui-typecheck`/`ui-lint`/`ui-test`/`i18n` purely by the presence of `typecheck`/`lint`/`test`/`i18n:check` scripts in `app/package.json` (verified by reading the gate block) — defining them is the switch. **Open owner decision (review F03)**: `@testing-library/react` 16 requires the peer `@testing-library/dom ^10` (verified against the npm registry: non-optional peer) — that package is not a 00 §0.8 row, so adding it needs the owner's baseline approval (one-line §0.8 addition riding this PR). **Alternatives**: adding `dockview` now (rejected — WP-05's composition concern, G-02); any virtualization library (rejected — not a baseline row, see D10).
- **D2 — Theme/accent mechanism.** **Decision**: `tokens.css` defines the token custom properties twice — `[data-theme="dark"]` (07 §7.4.1 values) and `[data-theme="light"]` (§7.4.2) — plus the timeline/media tokens per theme (§7.4.4) and the shared type/space/motion tokens (§7.4.5–7.4.6); accents swap `--accent-solid/text/subtle` via `[data-accent="clr-06|07|04|02|08"]` blocks using the §7.4.1/§12.17 values. High Contrast has **two** triggers per §7.4.3's own wording — "When `forced-colors: active` (Windows contrast themes) **or the user selects High Contrast**" — so the mechanism is: a `@media (forced-colors: active)` block that maps the tokens to system colors (§7.4.3) **plus** a `[data-theme="high-contrast"]` value applying the identical mapping for manual selection ( REQ-APP-009's "activates automatically" covers the first trigger; the second is §7.4.3's text — see the owner question in the plan review, F05). A Zustand `themeStore` sets `data-theme`/`data-accent` on `<html>`; switching is an attribute swap — no reload, satisfying REQ-APP-009's no-restart rule. **Rationale**: custom properties cascade and re-resolve on attribute change; one shared system-color mapping block serves both triggers, so nothing is duplicated by hand. **Alternatives**: CSS `color-scheme`-only theming (insufficient — the token set is much larger), relying on forced-colors alone (rejected — §7.4.3 names manual selection as a second trigger).
- **D3 — Application zoom 80–200%.** **Decision**: apply the standardized CSS `zoom` property on the app root element (`--app-zoom` holds the integer, clamped 80–200; the root declares `zoom: calc(var(--app-zoom) * 1%)` — multiplication by `1%` yields the percentage; division by a percentage is invalid CSS calc, review F09), driven by the same theme store; per-monitor DPI is left to WebView2's native device-pixel handling — all icons are SVG and all fonts variable, so scaling stays crisp (REQ-APP-010). The app zoom is the only zoom lever: the WebView's browser zoom (Ctrl+wheel/Ctrl+0) must be disabled by the shell (WP-05 wiring; recorded here so the interplay is a design fact, not a surprise). **Rationale**: `zoom` re-runs layout and scales px tokens, `rem`, and borders together (a `transform: scale` alternative clips and does not affect layout); it is standardized (CSS Viewport spec) and supported in WebView2/Chromium; the harness snapshots pin zoom at 100 for determinism. **Alternatives**: root `font-size` scaling (rejected — 07 §7.4.5 sizes are px tokens and would not scale), `transform: scale` (rejected — breaks hit-testing and scrolling).
- **D4 — i18n runtime and runtime language switch.** **Decision**: all six locale JSONs are statically imported into a typed registry (`{ en, ar, fr, es, de, "pt-BR" }`); an `IntlProvider` wrapper (react-intl 12) takes locale + messages from a `localeStore`; switching updates the store, which re-renders and sets `lang`/`dir` via `direction.ts` (07 §7.11) — no reload (REQ-I18N-001). The default resolves the Windows display language (`navigator.language`/`navigator.languages`) to a LOC-01..06 match, else `en`. **Rationale**: six small catalogs make static imports simpler and offline-safe (constitution VII); runtime switch is a provider prop change. **Alternatives**: dynamic `import()` per locale (unnecessary complexity at this size; revisit at WP-25 if catalogs grow).
- **D5 — Locale key discipline and CI check.** **Decision**: `app/src/locales/en.json` is the source; each other file must carry the exact same key set; `en.meta.json` carries one translator description per key (07 §7.12 rules 2/4). `pnpm -C app i18n:check` implements the full canonical localization gate (docs/08 §8.4: "keys identical in 6 locales, ICU syntax valid, no unused keys", review F06): deep key-set equality across all six files + `@formatjs/cli`'s ICU parser validating every message's syntax + a used-keys diff (message IDs extracted from the source by `eslint-plugin-formatjs`'s extractor) failing on unused catalog keys — nonzero exit on any violation (REQ-I18N-004). **Rationale**: the gate is defined canonically as three checks; all three are mechanically checkable; the script backs the existing `i18n` verify gate. **Alternatives**: equality-only (rejected — under-implements docs/08 §8.4), per-key fallback tolerance (rejected — REQ-I18N-004 says CI fails on missing or extra).
- **D6 — Component inventory mapping to React Aria Components.** **Decision**: all 41 components of 07 §7.6 are delivered (review F02). RAC 1.22 supplies the interactive core: Button, ToggleButton, Menu/MenuTrigger/Popover, Tabs, Dialog, AlertDialog, Tooltip, NumberField, Slider, Checkbox, Switch, RadioGroup, Select, ComboBox, SearchField, TextField, TextArea, GridList, Table, ListBox, ProgressBar, Meter, Spinner, Tree. Composed on top (RAC primitives + custom DOM): SegmentedControl (RadioGroup-styled), IconButton (Button + icon + Tooltip + accessible name), **MenuBar** (a `role="menubar"` wrapper over RAC menus with the ARIA menubar keyboard pattern across menus — verified against the registry/docs that RAC 1.22 ships no MenuBar primitive), **ContextMenu** and **Submenu** (menu-family compositions over MenuTrigger), Toast (region + announcer), **AngleDial** (custom dial alongside Slider), TimecodeField (four segmented fields, always `dir="ltr"`, scrub + typed/relative entry), KeyframeToggle/Navigator, ColorPicker (HSV square + hue + hex/RGB + recent colors), ColorWheel, CurveEditor (SVG), PointControl, Skeleton, Badge (text+icon), EmptyState, and the windowing collections wrapper (D10). **Rationale**: 07 §7.6 mandates RAC for interactive primitives; the specialist controls and the menubar are domain widgets the doc itself describes functionally. **Alternatives**: headless reimplementation of menu/dialog semantics (rejected — loses the ARIA/RTL guarantees REQ-A11Y-002 relies on).
- **D7 — Harness and deterministic snapshots.** **Decision**: a `/harness` route (`HarnessApp`) renders a story grid from `src/harness/stories/` (one file per component, nine states each: default, hover, focus-visible, pressed, disabled, error, RTL, compact, high-contrast); query params `?theme=dark|light&locale=<tag>&density=` select the rendering mode, so Playwright projects enumerate the dark/light × en/ar matrix by URL. The high-contrast state and the HC snapshots force `forced-colors: active` through a **CDP session** (`Emulation.setEmulatedMedia` with the `forced-colors` feature) — Playwright's `colorScheme` option covers only `light|dark|no-preference` (verified against the official emulation docs; WebView2/Chromium-only, which is the target). Playwright config: fixed viewport 1280×720, `reducedMotion: 'reduce'`, `await document.fonts.ready` before capture, `expect.toHaveScreenshot()` per story. `@axe-core/playwright` runs `axe()` per story in the same pass; any violation fails (T-A11Y-004, SC-006). **Rationale**: URL-driven modes reuse one build; reduced motion + awaited fonts + fixed viewport remove the classic flake sources; the CDP hook is the only documented way to exercise §7.4.3's mapping in tests (constitution III). **Alternatives**: per-mode builds (slow, drift-prone), component-test runners (no real CSS cascade), `colorScheme`-based HC (does not emit forced-colors).
- **D8 — Lint/build enforcement stack.** **Decision**: flat `eslint.config.js` (ESLint 9.39) with `typescript-eslint` strict-type-checked, `react-hooks`, `jsx-a11y` (errors), `eslint-plugin-i18next/no-literal-string` (JSX text literals error), `eslint-plugin-formatjs` (message-id hygiene); `.stylelintrc.json` (Stylelint 17 + `stylelint-config-standard` 40 + `stylelint-use-logical` 2 — physical margin/padding/etc. autofixed-flagged as errors); `.prettierrc.json` (Prettier 3) with `prettier --check` folded into the `lint` script so the single `ui-lint` gate covers formatting. `typecheck` = `tsc --noEmit` (strict, no `any`). **Rationale**: 02 §2.14 names each rule; the verify gates call exactly these scripts. **Alternatives**: separate format gate (none exists in verify.ps1 — folding keeps one command green).
- **D9 — Fonts FNT-01..03 bundling.** **Decision**: bundle variable woff2 files from the official upstream repositories (Inter: rsms/inter releases; Noto Sans Arabic: google/fonts repo; JetBrains Mono: JetBrains/JetBrainsMono releases) as separate files with each family's `OFL.txt` into `assets/fonts/`; a committed `fonts.json` records `{ id, family, file, sourceUrl, sha256, licenseFile }` per 12 §12.16; `fonts.css` declares `@font-face` with the §7.4.5 stacks and `font-display: swap`; the Arabic `:lang(ar)` line-height/size adjustment lives in tokens.css (§7.4.5). The integrity check (re-hash every file, assert each license present) runs in `pnpm -C app test` — matching the contracts (review F10). **Rationale**: 12 §12.16 pins OFL, separate files, license files, and the manifest "at WP-04"; bundled = no runtime download (constitution VII); the notices-manifest listing is tracked as D16. **Alternatives**: npm font packages (indirect provenance — the doc names upstream repositories + recorded hashes).
- **D10 — List virtualization beyond 200 rows.** **Decision**: implement a small `useWindowing` hook (container measurement + row height + overscan window; render window only) used by Tree/GridList/Table/ListBox above 200 rows (07 §7.6). **Rationale**: no virtualization library exists in the 00 §0.8 baseline; adding one needs an owner ADR (G-11/G-17); the doc's requirement is a threshold behavior, not a library. **Alternatives**: `react-virtuoso`/`@tanstack/virtual` (both rejected — not baseline rows; revisit via ADR only if the custom hook proves insufficient in WP-08's real timelines).
- **D11 — Mock backend skeleton.** **Decision**: `src/harness/mock/` exports typed fixture factories (media items, jobs, markers) shaped by the existing `src/ipc/bindings` types where they exist, plus a stub event bus — just enough for stories (badges, progress, lists, empty states); no IPC calls. **Rationale**: the card's "mock backend skeleton" is story data, not a fake server; the bindings keep fixtures honest to the model. **Alternatives**: a full command-mock layer (WP-05's need, not ours).
- **D12 — Theme/locale persistence seam.** **Decision**: `themeStore`/`localeStore` (Zustand 5) expose `set()` plus a storage seam interface (`read()/write()`); the harness binds the seam to URL query params; the app later binds it to `alvs.appearance.*` settings keys (WP-05/WP-24). **Rationale**: REQ-APP-009/REQ-I18N-001 need persistence to exist without inventing the settings wiring that belongs to later packages (FR-018 fence). **Alternatives**: reading `settings.json` now (rejected — storage ownership is WP-05's startup, CMP-12).
- **D13 — Accessibility infrastructure.** **Decision**: `components/a11y.ts` mounts the two live regions (polite for edits/jobs, assertive for errors — §7.13 rule 3) at the harness root and exports announcement helpers; focus ring comes from `--focus-ring` on `:focus-visible` (§7.13 rule 1); landmarks (banner/toolbar/region/status) are laid out by `HarnessApp` (§7.13 rule 2). Canvas `role="application"`/`aria-roledescription` patterns are documented in the contracts for WP-08+ consumers (§7.13 rule 4). **Rationale**: REQ-A11Y-002's "(components)" share is exactly the primitives + live-region infrastructure later screens reuse.
- **D14 — Pseudo-locales LOC-90/91.** **Decision**: `i18n/pseudo.ts` generates `en-XA` (accented Latin, +40% length, wrapping brackets) and `ar-XB` (**RTL, mirrored, bidi marks** — all three properties of 12 §12.14's LOC-91 definition, review F12) from `en`/`ar` at test time (pure string transforms); loaded only in test/harness builds via the registry; the expansion test renders toolbar/button labels under LOC-90 (07 §7.12 rule 5). **Rationale**: generated = cannot drift from the source catalog; test-only per the LOC table's Status column. **Alternatives**: checked-in pseudo files (drift; rejected).
- **D15 — CI wiring (review F07).** **Decision**: this package extends the existing `ui` job in `.github/workflows/ci.yml` (whose header says absent steps "are added by their owning work packages") to run `pnpm -C app typecheck && pnpm -C app lint && pnpm -C app test && pnpm -C app i18n:check` after the existing build + license check, plus a `ui-harness` job running the Playwright suite with browser install/caching; the pnpm 12 build-scripts approval for Playwright's browser/postinstall is added to the root `package.json` (`pnpm.onlyBuiltDependencies`, 05 §5.6 rule 4). **Rationale**: G-08 requires the gates to pass "in CI before merging", not only locally; defining the scripts without CI steps would leave the activation half-done. **Alternatives**: local-only gates (rejected — violates G-08), a separate workflow file (unnecessary — the `ui` job is the owner-designated home).
- **D16 — Notices manifest (review F08).** **Decision**: 12 §12.16 requires the font families to be "listed in the notices manifest" and no notices manifest exists in the repository yet — **open owner question**: whether WP-04 creates a minimal `NOTICES`/manifest artifact (recording FNT-01..03, OFL-1.1, and the ISC Lucide base set) or whether the manifest is a later package's deliverable (e.g., the release SBOM) and WP-04 records licenses only in `fonts.json` + this research note. Until answered, the plan does not claim the manifest as delivered; constitution IX's evidence cites the OFL/ISC license files in the bundle. **Rationale**: G-12 binds third-party assets to a compatible license "recorded in the notices manifest"; inventing the manifest's location/format without the owner would violate G-01. **Alternatives**: silently creating a manifest format (rejected — G-17).

**Zero unresolved clarifications** — the spec's assumptions cover the remainder.
